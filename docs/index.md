# Trunk Provider

Manage [Trunk](https://trunk.io) merge queues as code.

## Authentication

Use an API key. An organization admin creates one under **Settings** → **Developer** → **API Keys** in the Trunk app, with the **Update Merge Queue settings** permission. Give it to the provider in `api_key` or the `TRUNK_API_KEY` environment variable.

The provider picks the API from the credential. An API key (starts with `trunk_v2_`) uses the [v2 API](https://docs.trunk.io/merge-queue/reference/api-v2). The organization API token, in the **Organization API token (v1)** section of the same page, still works but uses the v1 API, which will be deprecated soon. Both manage the same settings; with an API key, the provider also reports each queue's `queue_id` and whether it has been changed outside Terraform (`managed_state`).

Upgrading from 1.x? See the [upgrade notes](https://github.com/trunk-io/terraform-provider-trunk/blob/main/CHANGELOG.md#200).

```terraform
terraform {
  required_version = ">= 1.0"
  required_providers {
    trunk = {
      source  = "trunk-io/trunk"
      version = "~> 2.0"
    }
  }
}

# Set the credential here or in the TRUNK_API_KEY environment variable.
# An API key (trunk_v2_...) uses the v2 API; the organization API token uses v1.
provider "trunk" {}
```

## Schema

### Optional

- `api_key` (String, Sensitive) A Trunk API key (`trunk_v2_...`, with the **Update Merge Queue settings** permission), which uses the v2 API, or the organization API token, which uses the v1 API. Can also be set with the `TRUNK_API_KEY` environment variable.
- `base_url` (String) The Trunk API host. Defaults to `https://api.trunk.io`. A trailing `/v1` or `/v2` is ignored, since the provider picks the version from the credential. Can also be set with the `TRUNK_BASE_URL` environment variable.
