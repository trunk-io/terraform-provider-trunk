# Trunk Provider

Manage [Trunk](https://trunk.io) merge queues as code.

## Authentication

The provider takes one credential, in `api_key` or the `TRUNK_API_KEY` environment variable, and picks the API from it:

- **An API key** (starts with `trunk_v2_`) uses the [v2 API](https://docs.trunk.io/merge-queue/reference/api-v2). It needs the **Update Merge Queue settings** permission. Create one under **Settings** → **Developer** → **API Keys** in the Trunk app.
- **The organization API token** uses the v1 API, which will be deprecated soon. It is in the **Organization API token (v1)** section of the same page.

Both manage the same settings. With an API key, the provider also reports each queue's `queue_id` and whether it has been changed outside Terraform (`managed_state`).

```terraform
terraform {
  required_version = ">= 1.0"
  required_providers {
    trunk = {
      source  = "trunk-io/trunk"
      version = "~> 2.0"
    }
  }
}

# Set the credential here or in the TRUNK_API_KEY environment variable.
# An API key (trunk_v2_...) uses the v2 API; the organization API token uses v1.
provider "trunk" {}
```

## Schema

### Optional

- `api_key` (String, Sensitive) A Trunk API key (`trunk_v2_...`, with the **Update Merge Queue settings** permission), which uses the v2 API, or the organization API token, which uses the v1 API. Can also be set with the `TRUNK_API_KEY` environment variable.
- `base_url` (String) The Trunk API host. Defaults to `https://api.trunk.io`. A trailing `/v1` or `/v2` is ignored, since the provider picks the version from the credential. Can also be set with the `TRUNK_BASE_URL` environment variable.
